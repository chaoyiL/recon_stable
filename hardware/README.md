# 灯带控制器

Python 上位机配置灯带布局和颜色，通过串口发送整帧 RGB；Arduino 校验后刷新 WS2812 灯带。数量由每帧指定，当前 Uno 固件支持总数 1–128 颗，包含开头空出的灯珠。

## 配置和运行

仓库根目录的 `config.yaml` 中，`led_controller` 指定四边灯珠数量、空出数量和输出校正。默认上、下各 9 颗，左、右各 4 颗，开头空出 3 颗。也可以改为：

```yaml
led_controller:
  top: 12
  right: 5
  bottom: 12
  left: 5
  skip: 2
  brightness: 30
  rgb_scale: [1.0, 1.0, 0.35]
```

此配置控制 34 颗灯珠，前面另有 2 颗始终熄灭，实际发送 36 颗。每一边允许为 0，四边至少保留一颗；五项相加不能超过 128。

在仓库根目录运行：

```bash
uv sync --locked
uv run python -m hardware.led_controller
```

命令行可以覆盖 YAML 中的数量：

```bash
uv run python -m hardware.led_controller --top 12 --right 5 --bottom 12 --left 5 --skip 2
```

`--config PATH` 可以选择其他配置文件。界面中的“应用布局”立即调整布局，保留各边已有灯珠的颜色，新增灯珠按默认配色初始化；界面修改仅对本次会话生效，持久配置请修改 YAML。较大的布局可以水平或垂直滚动。

灯带按以下顺序串接，编号从 0 开始：

| 段 | 物理方向 |
| --- | --- |
| 空出 | 灯带最前面的 `skip` 颗，始终发送黑色 |
| 上 | 从左向右 |
| 右 | 从上向下 |
| 下 | 从右向左 |
| 左 | 从下向上 |

按钮显示实际灯带索引。例如 `skip: 2` 时，第一颗可调灯珠编号为 2。空出段不参与颜色编辑，整体亮度和“应用到全部”也不会使其点亮。

选择灯珠后可以调整 RGB 和单颗亮度；整体亮度作用于四边全部灯珠。默认配色保持左蓝、右绿、上边红色叠加蓝绿渐变、下边蓝绿渐变，渐变按各边数量重新计算。“恢复默认”重新生成当前布局的配色。

## 胶皮颜色校正

`brightness` 设置启动时的整体亮度，取整数 0–100；`rgb_scale` 按 R、G、B 顺序设置三个 0–1 的固定输出系数。省略时分别为 100 和 `[1, 1, 1]`。按钮和调色板表示逻辑颜色，发送时才应用输出校正；界面显示当前固定系数。

当前配置使用整体亮度 30%、`rgb_scale: [1.0, 1.0, 0.35]`，配合相机曝光 20、白平衡 6500 K、背光补偿 0。该组合已在当前安装下实拍验证，保留四边彩色分布并减少胶皮蓝通道饱和。它是整套灯光、胶皮和相机的经验校正，不能直接迁移到另一套设备。完整证据见 [偏蓝诊断与调整记录](../docs/color_balance.md)。

启动控制器并连接 Arduino 后，再运行 `uv run capture`。采集默认将线性 RGB 编码为 sRGB 预览，按 `l` 可切换未编码的线性数值预览。PNG 和录像保存相机原始编码帧。更换灯光或相机参数后，应在同一设置下重新采集参考图、法向标定图并重新拟合 LUT。

## Arduino 固件和发送

首次使用新协议时，先在 Arduino IDE 打开 [led_arduino.ino](led_arduino/led_arduino.ino)，安装 **Adafruit NeoPixel** 库，选择开发板和串口后上传。默认数据引脚为 **D6**，灯珠类型为 **WS2812 / GRB / 800 kHz**，与原固件一致。

**新版协议与原来的固定 26 颗协议不兼容，Python 与 Arduino 必须同时更新。**

启动 Python 界面，选择 Arduino 串口并点击“连接”。上位机会等待约 2 秒让 Uno 完成串口复位，然后发送当前完整状态。调整颜色、亮度或应用新布局后自动发送，也可以点击“重新发送”。下位机确认后显示“已发送 N 颗”；未收到确认会明确显示超时。

串口波特率为 **115200**，数据包为：

```text
AA 55 | N_low N_high | R0 G0 B0 ... R(N-1) G(N-1) B(N-1) | XOR
```

`N` 是包含空出段的总数量，使用 16 位小端整数。帧长为 `3N + 5` 字节，XOR 覆盖数量的两个字节和全部 RGB，不含帧头。开头 `skip × 3` 个颜色字节固定为零，其余通道发送值为 `int(原始通道值 × 单颗亮度 / 100 × 整体亮度 / 100 × 对应 rgb_scale)`。

| Arduino 返回 | 含义 |
| --- | --- |
| `K` | 校验通过并已刷新 |
| `E` | 校验失败，保留原灯带状态 |
| `L` | 数量不在 1–128 范围内 |
| `M` | 灯带缓冲区分配失败 |

Arduino 启动时先熄灭容量内的灯珠，此后收到完整有效帧才更新输出；字节间超时超过 200 ms 会丢弃未完成帧。改变数量时先按旧长度熄灭，再调整驱动长度，避免缩短后尾部残留亮灯。

128 是当前针对 Uno 内存设置的容量上限，并非固定工作数量。若改用更大内存的板子，需要同时调整 `hardware/led_protocol.py` 和固件中的 `MAX_LED_COUNT`，并重新核对内存和灯带供电。

## 环境和串口权限

`pyserial` 已声明在项目依赖中。Tkinter 属于 Python 的可选系统组件，不通过 pip 安装。使用 Ubuntu/Debian 系统 Python 时可安装：

```bash
sudo apt-get install python3-tk
```

程序需要在可访问桌面显示服务的会话中运行。若连接 `/dev/ttyACM0` 时提示 `Permission denied`，可为当前设备临时授权：

```bash
sudo setfacl -m "u:${USER}:rw" /dev/ttyACM0
```

设备路径以实际枚举结果为准；重新插拔后临时授权可能失效。要长期允许当前用户访问串口，可加入 `dialout` 组，并注销桌面后重新登录：

```bash
sudo usermod -aG dialout "$USER"
```

协议和布局检查：

```bash
uv run python -m unittest discover -s tests -p test_led_protocol.py
```
